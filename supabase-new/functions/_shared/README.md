# _shared: the Google integration library and the three OAuth functions (m61, design 07)

Pure ESM, **no Deno-only and no Node-only API** (Web `crypto.subtle`, `fetch`, `URL`, `AbortController`, `TextEncoder`): the same files run in the Supabase Edge Runtime and under `node --test`. The Deno entry points (`../google-oauth-start/index.ts`, `../google-oauth-callback/index.ts`, `../google-disconnect/index.ts`) are 10 lines each: they pass `Deno.env` and supabase-js' `createClient` to `createEdgeRuntime` (`google-edge.js`).

```js
import { makeMimeMessage, sendGmailMessage, buildEventInsert, calendarInsertOrAdopt, resolveSender, getGoogleConfig, createEdgeRuntime } from '../_shared/google.js'
```

| File | What is in it |
|---|---|
| `google-core.js` | `GoogleError` / `ConfigError`, base64url / SHA-256 / HMAC, `getGoogleConfig(env)` (env only; address overrides need `ALLOW_FAKE_GOOGLE=1`), `signState` / `verifyState` (HMAC over user id + nonce + PKCE challenge + expiry + system flag + return path; constant-time check), `sanitizeReturnPath`, PKCE (`generateCodeVerifier`, `codeChallengeS256`, `deriveCodeVerifier`), `buildAuthUrl`, `httpRequest` (hard timeout, no redirects, body cap), `exchangeCode`, `refreshAccessToken`, `revokeToken`, ID-token claim validation, AES-256-GCM (`createKeyring`, `encryptToken`, `decryptToken`, key rotation), `chooseStorageMode` + `createTokenStore` (Vault or AES behind one interface), `createAccessTokenProvider` (in-memory access tokens, one shared refresh, `invalid_grant` -> `needs_reconnect`), `safeLog` (redacts secret-looking keys) |
| `google-mime.js` | `makeMimeMessage` (RFC 5322 / 2045 / 2047: UTF-8 Arabic subjects and names as encoded words cut on character boundaries, `multipart/alternative` text + HTML in base64, CRLF, Message-ID, Date, Reply-To, Cc; every address and header value is validated or neutralised: header injection is impossible), `htmlToText`, `textToHtml` |

| `google-edge.js` | `createRpcDb` (the service-role RPC adapter; `RPC_CONTRACT` pins every name and argument), `createEdgeRuntime` (config, JWT check, token store choice, handlers, `accessTokens()` for the workers) |

## The three functions
| Function | JWT | Body | Answer |
|---|---|---|---|
| `google-oauth-start` | verified (default) | `{ system?: boolean, returnTo?: "/path" }` | `{ url }` (Google's consent URL with a signed single-use state) |
| `google-oauth-callback` | **off** (`--no-verify-jwt`): Google's redirect has no login, the signed `state` is the protection | GET `?code&state` (or `?error`) | 302 to `APP_URL + returnTo + ?google=connected` or `?google=error&reason=<fixed list>` (`&target=system` for the system sender) |
| `google-disconnect` | verified | `{ system?: boolean }` | `{ ok, disconnected, revoked_at_google }` |

Secrets and variables: `../../../db/scripts/fake-google/functions.env.example` (names) and `docs/design/10-google-integration-setup.md` (what to click). The database side is `db/migrations/m61_google_oauth.sql`; the only reader of a token is `public.google_secret_get`, executable by `service_role` only.

## For the next functions (m62 e-mail worker, m63 calendar sync)
* Sender: `await db.resolveSender(actingUserId)` (= `public.resolve_sender_connection`) -> a connection id or null; `runtime.accessTokens().getAccessToken(connectionId)` -> an access token (throws `GoogleError` with `needsReconnect` on `invalid_grant`, after marking the connection `needs_reconnect`); call `db.touchConnection(id)` after a success.
* E-mail: `makeMimeMessage({ from: senderFrom(resolved, { pmName }), to, cc, replyTo, subject, html, messageId: '<outbox-id@athareg.com>' })` -> `sendGmailMessage(cfg, accessToken, raw)`. On `err.outcomeUnknown` park the row as `needs_review` and NEVER resend automatically.
* Calendar: `buildEventInsert({ bookingId, ... })` -> `calendarInsertOrAdopt(cfg, token, built)` -> `waitForConference(cfg, token, built.id)`; patch / delete by `built.id`.
* Tests: start the fake Google from `db/scripts/fake-google/server.mjs` and use `tests/helpers/` (`makeEnv`, `createMemoryDb`) as the model.

## The calendar sync (m63): `calendar-sync.js` + `../calendar-sync/index.ts`
Same rules as the rest of this folder (pure ESM, no Deno-only / Node-only API). `planJob(ctx)` is the one place that decides what happens to a job (shadow mode logs exactly this plan, live mode executes it); `buildDesired` / `eventTexts` build the event from stored data; `classifyError` / `backoffSeconds` decide retry, park or dead; `createCalendarDb(client)` is the service-role RPC adapter (the argument names are pinned by `CALENDAR_RPC_CONTRACT` and `tests/calendar-rpc-contract.test.js`); `createCalendarWorker({ db, getConfig, getTokens, ... }).runOnce()` is one pass (Google config and tokens are created lazily: shadow and off need no Google credentials). `google-calendar.js` gained two optional `buildEventPatch` parameters (`status`, `conferenceRequestId`). Tests: `tests/calendar-sync.test.js` (pure logic + the worker against the fake Google with the in-memory database twin `tests/helpers/memory-calendar-db.js`), `tests/calendar-rpc-contract.test.js`. Operations: `../calendar-sync/README.md`.

## The e-mail worker (m62): `email-worker.js` + `email-worker-edge.js` + `../email-worker/index.ts`
Same rules as the rest of this folder (pure ESM, no Deno-only / Node-only API). `email-worker.js`: `runEmailWorker(deps, opts)` is one run (claim -> build -> token -> **persist the request marker** -> send -> finish; an unknown outcome is parked as `needs_review` and NEVER resent; 401 retried once; `invalid_grant` -> needs_reconnect + the fallback sender; 429 / 5xx retry with exponential backoff + jitter and a maximum streak; per-sender circuit breakers inside a run; a deadline that RELEASES untouched rows), `classifySendError` / `classifyTokenError` / `backoffMs` / `buildOutgoing` (Message-ID `<outbox id.attempt@domain>`, CC cleaning, Arabic subject through `makeMimeMessage`), `createEmailDb(client)` is the service-role RPC adapter (the argument names are pinned by `EMAIL_RPC_CONTRACT` and `tests/email-rpc-contract.test.js`), `authorizeWorkerRequest` (constant-time shared-secret check, fail closed). `email-worker-edge.js`: `createEmailWorkerHandler` (POST only, the secret first, body options that can only LOWER the limits, a 503 that lists env NAMES). Tests: `tests/email-worker.test.js` (43: pure logic + the worker against `tests/helpers/memory-outbox.js`, an in-memory twin of the m62 RPCs), `tests/email-worker.fake.test.js` (10: the same worker over HTTP against the fake Google: decoded Arabic subject, 429 + Retry-After, 503, 401, invalid_grant + fallback, timeout / reset after accept = needs_review and no resend), `tests/email-worker-edge.test.js` (8), `tests/email-rpc-contract.test.js` (10). Operations, scheduling and the outcome table: `../email-worker/README.md`.
