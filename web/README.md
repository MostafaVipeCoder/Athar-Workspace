# Athar web (new frontend skeleton)

The new Athar frontend (design `docs/design/06-frontend-architecture.md`). Lives beside the old app (`src/` at the repo root), which stays the deployed one until cutover. Stack: React 19 + JavaScript + Vite 7 + Tailwind 3 + react-router-dom 7 + TanStack Query 5 + supabase-js. The project canvas (`@xyflow/react`, React Flow 12) is lazy-loaded only on `/projects/:id` (one chunk, see "Canvas"). SheetJS (`xlsx`) is loaded only through `lib/export/xlsx.js` (dynamic import).

## Run

Prerequisite: the local Supabase stack is running (`cd local-db/stack && npx supabase status`).

```
cd web
npm install
cp .env.example .env.local     # then fill the two VITE_SUPABASE_* values (see below)
npm run dev:local              # http://127.0.0.1:5174  (mode "development", reads .env.local)
npm run dev:lan                # the app on the local network for a phone (iPhone / Safari test): see "Testing on an iPhone / Safari"
#   (from the repo root: npm run dev:local --prefix web; .claude/launch.json has a "web-local" entry)
npm run build && npm run preview
npm run lint
npm test                       # Vitest + Testing Library
```

`.env.local` is git-ignored. Local values: `VITE_SUPABASE_URL=http://127.0.0.1:54321` and the local anon key printed by `npx supabase status -o env` (`ANON_KEY`). Never commit keys. If a variable is missing the app shows a bilingual ConfigError screen (no fallback to a live project). `EnvBanner` shows green "LOCAL DB" or red "LIVE DATA" from the URL host.

Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_APP_ENV` (local|staging|production), `VITE_BASE_PATH` (default `/`; router basename and asset base), `VITE_APP_PUBLIC_URL` (optional).

On some Windows machines port 5174 sits in a reserved (excluded) TCP range and cannot be bound (`netsh interface ipv4 show excludedportrange protocol=tcp`): run `npx vite --mode development --host 127.0.0.1 --port 5400` instead.

## Key behaviours

- Auth: `AuthProvider` is query-based (roles from `user_roles` under RLS; no role cache in storage; the cache is wiped when the identity changes). `RequireAccess` is the only guard (decision table in `lib/access.js`, unit-tested); `/` is `RoleHome`.
- i18n: `useLanguage()` gives `t, tn, pick, formatDate, formatNumber, lang, dir, setLang`. Resolution: `?lang=` then stored `athar.lang` then default per area (staff `en`, rest `ar`). `<html lang dir>` is set once. Western digits in Arabic.
- Legacy URLs: `app/legacy/legacyRedirects.js` (one table + boot shim for `#/...` and `?agenda=`).
- Placeholder routes render `ComingSoon` with the step number from design 06 section 14.
- Time: store UTC, build/display wall-clock values only through `lib/time` with the PROJECT timezone (`projects.timezone`, one IANA zone, default Africa/Cairo). Never `new Date('YYYY-MM-DD')`.
- Images (universal WebP, owner decision 08 section 17.3; see "Universal WebP" below): `data/storage.uploadImage(file, { ownerId, kind })` converts in the browser through `lib/image` (profile by `kind`, EXIF, alpha, quality ladder, size guard) and stores `<owner>/<kind>/<uuid>.webp` + `<uuid>_t.webp` in `public-assets`; the DB keeps only the full path (`publicThumbUrl` derives the thumbnail). `data/storage.js` is the only module allowed to write files (ESLint + a source scan), and the server refuses PNG / JPEG in the image buckets (m41).
- Staff management (super_admin): `/admin/staff` lists staff, changes roles / program access, removes, invites by e-mail (RPCs of migration m24). The invitation link is shown once (copy button) because e-mail delivery is not wired yet. Invitees register at `/invite/staff/:token` with name + password + colour only; the DB trigger never grants `founder` on that path. `/profile` edits name, colour, language, password.

## Canvas (`src/app/canvas`, design 06 section 3)

- `ProjectPage` renders the header and `lazy(() => import('../canvas/ProjectCanvas.jsx'))`: that file is the only one importing `@xyflow/react` (and its CSS), so the canvas chunk (about 200 kB / 66 kB gzip) is paid only by PMs on the canvas route. Attribution stays on (owner, 08 section 14).
- Data: one query `get_project_graph` (`useProjectGraph`, nodes without config + edges + revisions) and the mutations of `data/canvas.js` (`useCanvasMutations`): `add_node`, `move_nodes` (optimistic, debounced 800 ms after a drag, never bumps a revision), `delete_node` (soft delete) / `restore_node` (the Undo in the toast), `connect` / `update_edge` / `disconnect`, rename through `save_node` (optimistic-concurrency token = the node's rev), duplicate (= `add_node` of the same type + extension options + `save_node` of the config). Every success refetches the graph; errors are shown by the canvas (toast + inspector status), not by the global reporter.
- Pure logic in `canvasModel.js` (unit-tested): `validateCanvasConnection` mirrors design 02 section 2.5 and the DB trigger `validate_edge` (families, kind, duplicate, cardinality, then `wouldCycle` = DAG **per port family**, decision 02-13). The DB is the authority: when it rejects a connection the server message is shown. Also graph -> React Flow mapping (`toFlowNodes`/`toFlowEdges`, colour per family), default names (`"<Type> N"`), overlap-free placement, sidebar items (booking presets expanded).
- UI: `ToolSidebar` (registry groups, search, drag source + tap "+" which adds at the viewport centre; collapsible on phones), `NodeCard` (memoised; one `<Handle>` per port: inputs LEFT, outputs RIGHT in both languages because the canvas world is `dir="ltr"`; the card text follows the UI direction), `NodeInspector` (summary, status saved/saving/error + "updated just now" flash from the revision poll, ports with counterparts, View/Edit/Settings links, rename/duplicate/delete; edge: audience + enabled + remove; right column on desktop, bottom sheet on phones). The implicit `view_host` system node is shown locked (not deletable) with a link to the public project page.
- Keyboard: Delete/Backspace removes the selection (ConfirmDialog first), Esc deselects. Multi-user: `useSavedStateRefresh` polls `get_graph_revisions` (focus + 30 s); a changed or new/removed node refetches the graph and flashes the changed cards.

## Mentoring Distribution node (`src/nodes/distribution`, design 01 section 3.7, 02 section 4/12, 03 section 9.4, decision 01-7)

- The fixed timetable of the offline 1-1 sessions in the hall: mentor x round x day -> company. Ports mirror the DB row: in `mentors` + `companies` (Lists' `items`, BY REFERENCE: sessions point at `list_items` ids, names/photos are resolved by the DB, never stored on a session), optional `schedule` (an Agenda's days: `distribution_days.agenda_day_id` supplies the date; without it the node keeps its own date, 02-12); out `sessions-tab` (the matrix) and `my-meetings-tab` ("My schedule / Who do I meet next") = Agenda tabs through the tab contract. The Live board is a standalone page.
- Rules (01-7): ONE break model = the per-day gap; total round = slots + gaps (`lib/time/slots`); a locked day is never overwritten (Generate, Regenerate, config saves, removal all refuse it); unique pairing is per node; the project timezone is used everywhere (`lib/time`), "today" included.
- **The algorithm** (`matching.js`, pure + seeded + unit-tested): per round ONE optimal assignment (Hungarian) maximising filled cells, then fairness, then a seeded jitter; 8 attempts, best kept; windows / allowed days / max per day honoured by every path; every empty cell explained. The server never trusts it: `replace_distribution_sessions` re-validates every row and swaps the sessions atomically. Manual edits (drag/swap/move, click dialog, clear) are ONE `set_distribution_session_companies` call each (hard conflicts raise, repeated pairs warn) with an Undo toast = the inverse call; sessions have DB ids from creation.
- Edit = Setup (round, days, mentors x days, availability: window / max per day / room; draft + ONE `save_node` with children) / Timetable (Generate, Regenerate unlocked, per-day lock and regenerate, seed, matrix editing, issues, publish, Excel, print) / Live (PM remote + board). Settings = name, visibility, show-to-participants, publish, timer alert + sounds, the Matrix and Live links. View = the PM preview of the three surfaces.

## Universal WebP (`src/lib/image`, `src/data/storage.js`, `src/ui/ImageField.jsx` + `Img.jsx`, migration m41; owner decision 08 section 17.3)

Every image uploaded from ANY place of the platform is converted to WebP before it is stored and is displayed in that format everywhere. One pipeline, enforced in four layers (the first two make it impossible to forget, the last two catch what is not the browser):

1. **The browser pipeline** `lib/image` (import from `lib/image/index.js` only; `data/storage.js` itself imports only the tiny `errors` / `paths` / `profiles` modules and loads the converter with a dynamic `import('../lib/image/convert.js')` inside `storeImage`, so the 40+ chunks that merely SHOW an image do not carry the pipeline: the `storage` chunk is 3.0 KB, the converter is its own lazy chunk of 7.7 KB): `convertToWebp(file, { profile, onProgress, signal })` -> `{ profile, full, thumb, source, report }`. `data/storage.js` is the ONLY module that writes files: `uploadImage(file, { ownerId, kind })` (covers / photos / logos in `public-assets`, `<owner>/<kind>/<uuid>.webp` + `_t.webp`), `storeImage(file, { bucket, path(ext), profile })` (any image bucket; the caller builds the path from the stored extension), `uploadObject(bucket, path, body, { contentType })` (everything that is NOT an image; an `image/*` type is refused). A refused image becomes `AppError('validation', { messageKey: 'errors.image.<code>' })`.
2. **Lint + a source scan**: `.upload(` / `uploadToSignedUrl(` / `createSignedUploadUrl(` and a storage `.update(path, file)` (a replace: `<x>.storage.from(bucket).update(` or `store.update(` on a bucket handle) outside `data/storage.js` are ESLint errors (`eslint.config.js`; no exception any more) and `data/storage.guard.test.js` scans `src` for the same plus raw Storage REST calls, raster content types handed to storage, and stray canvas encoders. `uploadObject` also sniffs the first bytes: an image whose declared type is not an image (`application/octet-stream`) is refused as well.
3. **The doors** (`db/migrations/m41_webp.sql`): `allowed_mime_types` of `public-assets` = WebP + SVG (logos), `founder-assets` = WebP, `resources` and `form-uploads` lose png / jpeg / gif; two RESTRICTIVE policies on `storage.objects` (INSERT + UPDATE, anon + authenticated) refuse a raster NAME or a recorded raster mimetype in those four buckets. A PNG sent straight to the Storage API is answered HTTP 400 `invalid_mime_type`.
4. **The safety net**: `db/scripts/convert-images.mjs` (batch, sharp, dry run by default, never deletes) and the `supabase-new/functions/image-convert/` skeleton (not deployed) for the future live project, see "Server side" below.

**Profiles** (`lib/image/profiles.js`; the folder `kind` of `uploadImage` picks one, `profile` overrides it): `cover` 1920 px (program / project / agenda / form covers, share image `og`), `landing` 1920 px (hero + card covers, a little more quality), `content` 1600 px (library images and anything else), `avatar` 512 px (people photos), `logo` 512 px (alpha kept, **SVG accepted and stored untouched** after a safety check: no scripts / handlers / external references), `frame` 1350 px longest side, lossless first, alpha exact, no thumbnail (Landing frames: the 1080 x 1350 export grid), `template` 4000 px, quality 0.92, alpha kept, no thumbnail (**ready for the Certificates builder**), `attachment` 2000 px (pictures a respondent attaches to a public form, no thumbnail). Every profile except `frame`, `template` and `attachment` also makes a 320 px `_t.webp` thumbnail.

**Rules** (each one is unit-tested with a fake canvas backend, `lib/image/*.test.js`):
- The format comes from the BYTES (`sniff.js`: PNG / JPEG / GIF / WebP / AVIF / HEIC / BMP / TIFF / SVG / PDF magic numbers, pixel size, animation), never from `file.type` or the name. PDF, text, a truncated / damaged file (the browser may half-decode it; the file tail is checked), a HEIC the browser cannot decode, more than 100 megapixels or 25 MB all fail with their own ar / en message (`errors.image.*`); the original raster is NEVER uploaded as a fallback.
- EXIF orientation is applied (`createImageBitmap(file, { imageOrientation: 'from-image' })`), transparency is kept, the longest side is capped by the profile and never upscaled, big reductions go through halving steps (no aliasing).
- **Quality ladder + size guard**: the first quality whose result fits `min(profile target, source size)` wins; when nothing beats the source the SMALLEST WebP is kept (a WebP larger than the PNG is still the stored format, the server refuses the PNG). An already-WebP source that fits the profile is kept as it is (no generation loss) unless a re-encode is smaller.
- **Animated GIF / APNG: the FIRST FRAME is kept and the result says so** (`report.notices = ['animatedFirstFrame']`, shown in ImageField). Reason: WebP produced from a canvas is a still image, an animation is not what covers, photos and logos are for, and a 3 MB looping GIF is exactly the weight this decision removes. An animated WebP that already fits the profile is kept as it is.
- Memory-safe: `createImageBitmap` + `OffscreenCanvas` when the browser has them (no DOM canvas, no full-size copy in the page), the decoded bitmap and every intermediate canvas are released, a cancelled conversion stops between steps (`AbortSignal`). A browser whose canvas cannot ENCODE WebP (**Safari and every iOS browser answer PNG**) takes the WebAssembly fallback `lib/image/wasmWebp.js` (libwebp through `@jsquash/webp`, Apache-2.0): a DYNAMIC import chain that only such a browser ever starts (the two .wasm files, 281 KB / 345 KB with SIMD, are static assets fetched on demand, once per session); Chrome / Edge / Firefox never download a byte of it. When even the fallback cannot load (offline, blocked, no WebAssembly) the upload fails with `errors.image.webpUnsupported`: the original raster is NEVER uploaded instead. Development switch to exercise the fallback in Chrome: `window.__forceNoNativeWebp = true` before the first upload (dead code in a production build). Not yet tried on a real iPhone / Safari (no device here): the dev page `/dev/image-check` and `npm run dev:lan` (see "Testing on an iPhone / Safari") let the owner test it without engineering help.
- ONE conversion per (File, profile): ImageField converts when a file is picked (preview + feedback) and the data layer asks for the same result again (cached in a WeakMap).

**What the user sees**: `ui/ImageField` shows "Reading the image / Converting to WebP / Preparing the thumbnail / Uploading..." with a progress bar, then "Optimised: 2.1 MB -> 180 KB (-91%)" (or "Already WebP", "SVG kept as is", "Converted to WebP: 120 KB -> 140 KB" when WebP is not smaller, the animated-GIF notice); the preview is the converted image, i.e. exactly what is stored. The cover library toast, the Library upload toasts and the public form's file field show the same sentence. Props: `profile` must match the profile the page's upload uses (`uploadImage` derives it from `kind`: cover, form-cover and og = cover, landing, library = content, photo and avatar = avatar, logo).

**Display**: `ui/Img` (lazy by default, **the blurred thumbnail preview included** (a 141-card list no longer requests 141 thumbnails at load), `decoding="async"`, reserved `aspect` box = no layout shift, `thumb` blurred under the full image, `variant="thumb"` loads the thumbnail only: lists and cards use the `_t.webp`, detail views the full file, `priority` = eager + `fetchpriority="high"` for THE above-the-fold cover / hero, never for lists); `publicThumbUrl(path)` is the only place that knows the thumbnail convention (`thumbPath` in `lib/image/paths.js`; an SVG or a legacy raster is its own thumbnail); `ui/Avatar` has width / height + lazy + async. **Certificates**: since m42 the Certificates node uploads its template through `storeImage(file, { bucket: 'certificate-templates', path, profile: 'template' })` like everything else (WebP only; the bucket list and two restrictive policies refuse anything else) and the ESLint / guard-test exception is gone. Its size checks read the file HEADER (`lib/image/sniff`, no decode) and the editor previews the STORED, converted WebP (see "Certificates" above).

**Server side** (m41 + `db/scripts`): `app_private.nonwebp_image_objects` (view: every raster object of any bucket), `app_private.storage_dangling_refs()` (the proof that no DB reference points at a missing file or a missing thumbnail: every `*_path` column and every path-looking string in any jsonb column; empty = clean) and `app_private.rewrite_storage_refs(old, new)` (service role only: replaces a path in EVERY text / varchar / json / jsonb column of `public` in one transaction). `convert-images.mjs` (run through `bash db/scripts/run-convert-images.sh`, `SHARP_DIR` = a scratch dir OUTSIDE the repo with `npm i sharp`) scans every bucket, lists raster objects plus `.webp`-named objects whose bytes are not WebP, finds the references, and in dry-run (default) converts in memory and prints the saving; `--apply` (m45, owner decision 18.4: "convert all of them and delete the old originals") converts EVERY raster of EVERY bucket, referenced or not, to `<dir>/<base>.webp` (+ `_t.webp` where the bucket carries thumbnails), records it in `app_private.image_conversions`, rewrites every reference (also `migration.asset_result.archive_path`) and proves with `storage_dangling_refs()` that nothing dangles; it never deletes. A separate second run, `--delete-originals` (`--dry-run` previews), removes the originals THROUGH THE STORAGE API, only those with a verified WebP sibling, no reference left and an unchanged sha256, after writing `local-db/backups/deleted-originals-manifest.csv` (git-ignored: path, bytes, sha256). **Run on the local stack on 2026-10-14: 133 originals (83.3 MB) became 5.8 MB of WebP and were deleted, 18 stale metadata rows (file already missing) and 2 non-images were removed, and no raster is left in any bucket**; the numbers per bucket and what stays recoverable are in `db/MIGRATION-LOG.md` (m45) and `PROGRESS.md`. `supabase-new/functions/image-convert/` (+ `webhook.sql`, README) is the skeleton for the live project (Database Webhook on `storage.objects` INSERT -> normalise a mislabelled file in place / convert a stray raster and rewrite its references); the image codec is not wired and nothing is deployed.

**Known limits**: neither the bucket list nor the policies can look INSIDE the bytes (a PNG labelled `image/webp` with a `.webp` name is stored): that is what the batch / the edge function are for. Link-preview crawlers (LinkedIn, some WhatsApp versions) do not always render a WebP `og:image`: since m45 every SHARED image also has a JPEG derivative in the public bucket `og-images` (next section).

**Also**: a public form's file field judges a PICTURE by the pipeline's ceiling (25 MB source), not by the 10 MB stored-file limit that still applies to documents (`data/forms.js` `validateUploadFile`); the Landing frame editor shows the saving in its toast; the static login / 404 background `public/brand/pattern.png` is now `pattern.webp` (lossless, 204 KB instead of 442 KB; logos and the favicon stay PNG, they are 1 - 6 KB). The WebP-support probe of `lib/image/canvas.js` paints a pixel first: an `OffscreenCanvas` with no rendering context throws on `convertToBlob`, which made current Chrome look "unable to encode WebP" (found in the browser walk-through, see `PROGRESS.md`, "Universal WebP"). ## Link-preview JPEG: the `og-images` bucket (`src/lib/image`, `src/data/storage.js`, migration m45; owner decision 08 section 18.6)

LinkedIn and some WhatsApp versions do not render a WebP `og:image`. WebP stays the stored and displayed format; every image uploaded with a SHARING purpose ALSO gets a JPEG derivative:
- **Which images**: the pipeline profiles `cover` (program / project / agenda covers, the form cover library, the form share image `og`) and `landing` (hero, card covers, the SEO image) carry `og: true` (`lib/image/profiles.js`; the folder kinds `cover`, `project-cover`, `form-cover`, `og`, `landing` map to them). Library images, people photos, logos, frames, certificate templates and respondent files do not: nothing shares them.
- **What**: a 1200 x 630 JPEG, cover crop (the centre, what `object-fit: cover` shows), white behind transparency, progressive (mozjpeg through `@jsquash/jpeg`: a 252 KB `.wasm` (60 KB gzip) fetched only when a shared image is uploaded; where it cannot load, the canvas's own baseline JPEG encoder takes over), quality 0.82 stepping down by 0.08 to 0.52 until it is at most 300 KB (WhatsApp ignores a larger preview). The sizes of a real upload: a 4.2 MB JPEG cover gave WebP 148 KB + thumbnail 7 KB + JPEG 68 KB.
- **Where**: the PUBLIC bucket `og-images` (`image/jpeg` only, 1 MiB) at the path DERIVED from the source path, with no database column: `public-assets/<owner>/<kind>/<uuid>.webp` -> `og-images/<owner>/<kind>/<uuid>.jpg` (`ogPathOf` in `lib/image/paths.js`; SQL `app_private.og_image_path`; the server scripts `db/scripts/lib/plan.mjs`). A thumbnail, an SVG and a legacy raster have none.
- **Who writes**: only `data/storage.js` `storeImage` (a guard test enforces it, and that the bucket name lives in one place), in the same step as the WebP and thumbnail; a failed derivative NEVER fails the upload (`ogPath: null`, `ogError`, the notice `ogFailed`); `removeImage` removes it with the image. `publicOgUrl(path)` returns the public URL. `ui/ImageField` shows the extra line "Link preview (JPEG 1200 x 630): 68 KB" (ar + en).
- **Policies** (03 section 8): world-readable (crawlers fetch it anonymously); insert / update / delete only for a manager of the owner folder (project or program id) or a super_admin under `global/`, and only for names matching `<owner>/<kind>/<uuid>.jpg`; a JPEG is still refused in every other bucket (m45 extends the WebP-only rule from four buckets to ALL of them, `og-images` excepted).
- **Existing images**: `db/scripts/backfill-og-images.mjs` (`SHARP_DIR=<dir> bash db/scripts/run-backfill-og.sh [--apply]`) made the derivatives of the 18 shared images that existed before (7 project covers, 2 public-link previews, 5 form covers, 3 landing card covers, 1 landing hero; 1.0 MB). `app_private.og_missing_refs()` is its work list (empty = complete; v45 D03), `app_private.og_orphans` lists derivatives whose source is gone, `app_private.og_source_refs()` is THE definition of "a shared image reference": a new sharing source goes there and its upload kind gets `og: true`.

**How the future share / OG function (design 06 section 12.3; NOT built) resolves the `og:image` URL.** For the public item it renders (link -> project / node):
1. pick the SOURCE path: project / agenda page = `public_links.og_image_path`, else `projects.cover_path`, else the program cover; form = the node's `config.share.image_path`, else the form cover (`form_covers.image_path`); landing = `config.seo.imagePath`, else `config.hero.coverPath`, else the first card cover (the list of `app_private.og_source_refs()`);
2. derive the JPEG path: `ogPath = source.replace(/\.webp$/i, '.jpg')`, only for a `.webp` that is not `_t.webp` (or `select public.og_image_path(<source>)` with the service key: NULL when there is none);
3. emit `<meta property="og:image" content="<SUPABASE_URL>/storage/v1/object/public/og-images/<ogPath>">` (URL-encode each path segment) with `og:image:type = image/jpeg`, `og:image:width = 1200`, `og:image:height = 630` and `twitter:card = summary_large_image`;
4. when there is no derivative (NULL, SVG, a legacy raster, or a HEAD that answers 404) fall back to the generic Athar card image, never to the WebP.
The derivative exists for every image stored before m45 (backfill) and for every upload through the pipeline, so step 2 needs no lookup.

## Testing on an iPhone / Safari (`/dev/image-check`, `scripts/lan-dev.ps1`; owner decision 08 section 18.5) · اختبار على الآيفون / سفاري

**English.** Every iOS browser is WebKit, and Safari cannot encode WebP from a canvas: the app then uses its WebAssembly fallback (`lib/image/wasmWebp.js`). The development page `/dev/image-check` proves on the REAL device that uploads work, so the owner can test without engineering help. The page exists only in development (it is not in `npm run build`, like `/dev/nodes`) and needs no sign-in; nothing is uploaded or stored.
1. On the computer: start the local stack (Docker Desktop, then `cd local-db/stack && npx supabase start -x logflare,vector,imgproxy,edge-runtime,mailpit`), then in the `web` folder run `npm run dev:lan` (or `powershell -ExecutionPolicy Bypass -File web\scripts\lan-dev.ps1`). The script finds the LAN address, points the app of THIS process at `http://<that address>:54321` (`web/.env.local` is not touched) and starts Vite on port 5400 for the whole network. `-DryRun` only prints; `-Ip 192.168.x.x` picks an address; `-Port` changes 5400.
2. It prints the address for the phone, e.g. `http://192.168.1.7:5400/dev/image-check`. The phone must be on the SAME Wi-Fi. (A Mac with Safari can use the same address.)
3. If the phone cannot open it, Windows Firewall is blocking the two ports. The script prints the exact command (`New-NetFirewallRule ... -LocalPort 5400,54321`) for you to run yourself in PowerShell AS ADMINISTRATOR, and the `Remove-NetFirewallRule` that undoes it when you are done. The script never changes the firewall. (If the Wi-Fi is set to "Public" it says so: prefer switching it to "Private".)
4. On the iPhone open the address in Safari. Wait for the checks (green or yellow is fine, a yellow one is explained in the report). Tap "Choose a photo" and pick a photo from the library (best: a portrait photo taken with the phone held upright: it proves the rotation). The page shows the timings of each step, before / after bytes and sizes, whether the orientation is right, the converted picture next to the original and the link-preview JPEG. Tap "Copy report" (on an `http` address the copy button may not work: press and hold the report box, choose Select all, then Copy) and send us the text.
5. Stop the script with Ctrl+C. The same address without `/dev/image-check` is the whole app (sign in works against the same local database), so a cover upload from the phone can be tried too.
What the three checks mean: "WebP from the browser itself" (Chrome / Edge / Firefox: works; Safari: no, expected), "WebP fallback (WebAssembly)" (must work; this is what Safari uses), "Progressive JPEG (WebAssembly)" (the link-preview encoder). The verdict is green when everything works natively, yellow when the fallback is in use (expected on Safari, slower), red only when no way to make WebP exists (then no upload would work). On a computer the "Developer switch" pretends the browser cannot make WebP, to test the fallback in Chrome (it is dead code in a production build).

## Add a node type

1. Create `src/nodes/<folder>/manifest.js` with `defineNode({ key, version, name:{en,ar}, icon, category, ports:{in,out}, ... })`. Ports use families from `manifest.contract.js`; `key` must match a row in `public.node_types`.
   A port is `inPort(key, families[], label{en,ar}, { kind?, cardinality: 'one'|'many', required? })` / `outPort(...)` (helpers in `_kit/defineNode.js`). The canvas draws one handle per port; an edge is allowed when the output's FIRST family is accepted by the input, kinds match (list `items` is `kind: 'subkind'`, decided server-side from `lists.subkind`), the pair is not connected yet, the input's cardinality is not exceeded and no cycle appears within that family. Keep the manifest in sync with the `node_types.ports` row (m02) — the DB validates the same rules.
2. Components default to the shared placeholder. For real screens create `Edit.jsx`, `View.jsx`, `Settings.jsx` in the folder and set `components: { Edit: () => import('./Edit.jsx'), ... }` (lazy thunks, default exports).
3. Use the kit only: `useNodeConfig()` (draft + explicit Save + refresh; `save(extraPatch)` may add `name_en/ar`, `visibility`, `show_to_participants`), `useInputPort(key)` (reads upstream data through the SOURCE node's `ports.out[].resolve` thunk), `NodeFrame` (`showSave={false}` for row-level editors, `actions`, `subtitle`), `useNodeContext()`. Never import Supabase or another node; data goes through `data/` modules.
4. For an output port other nodes can read, give it `resolve: () => import('./data.js').then(m => m.resolveX)`; the resolver gets `{ node, port, adapter, graph }` and returns `{ items }`.
5. Register it in `src/nodes/registry.js`. `registry.test.jsx` validates the contract for every manifest.

The dev-only `note` node (`src/nodes/note`, playground at `/dev/nodes`) is the worked example. It is excluded from production builds (`devManifests.prod.js` alias in `vite.config.js`).

## Review fixes of the Alumni work (migration m52, 2026-10-14): rules every new page and RPC must follow
- **Never raise an application error with SQLSTATE 40001 / 40P01**: PostgREST 14 retries those for ever (a stale save made the request hang). Conflicts are `P0001` + a hint token (`revision_conflict` for `save_node`, `alumni_stale` for the Alumni saves); the client maps the TOKEN (`data/errors.js`, `TOKEN_CODES`). `db/verify/v52` C01 fails if any function of `public` / `app_private` raises either code.
- **A national ID never travels in a URL**: every function that takes or returns one starts with `perform app_private.alumni_post_only()` (HTTP 405 on GET / HEAD) and is VOLATILE. A new ID-bearing RPC must do the same and be added to v52 C03 / G.
- **One write path**: the web client writes `founders` and the typed columns of `companies` ONLY through the RPCs. `authenticated` has no INSERT / UPDATE on `founders`; on `companies` it holds column privileges (a NEW column is not client-writable until a migration grants it) and the trigger `companies_biu_write_guard` re-applies the RPC's checks to a direct write. The PM Lists node still inserts companies (name / industry / description / logo / links / origin project) through `data/people.js`.
- **Unknown is not zero**: team counts are `null` when nobody is recorded / no gender or age is known (dash in the UI, blank cell in Excel: `exportRows(..., { blanks: true })`).
- **Accessibility helpers**: `Field` / `BilingualField` errors are `role="alert"` and wired with `aria-invalid` + `aria-describedby`; `focusFirstInvalidSoon(form)` after a failed submit; `SkeletonList` (loading status text) instead of a bare `aria-busy` box; `ConfirmDialog` focuses the SAFE button first (Cancel when `destructive`); `RouteTitle` names every page after its first `<h1>`; text colours of statuses use `text-success-text` / `text-destructive-text` (AA), never `text-success` for text; targets are `min-h-11` (44 px); counts before a noun go through `tn()` with plural objects (Arabic: zero / one / two / few / many / other) and the Arabic dictionaries use Western digits.
- **Shared helpers added**: `lib/clipboard.js` (`copyText`: the ONE copy implementation), `lib/badge.js` (`badgeCount`, no imports: the founder shell needs only this), `i18n/core.js` `joinList(lang, items)`, `lib/alumniFounder.js` `notificationText(n, lang)` (a broadcast keeps both languages in its metadata).

## E-mail Outbox (`src/data/outbox.js`, `src/lib/outbox.js`, `src/shared/outbox/*`, pages `OutboxPage` and `staff/EmailHealthPage`; migration m62; design 07 section 1; the function: `supabase-new/functions/email-worker/README.md`)
- **What it is**: the platform never sends mail from the browser. Every producer (Selection, Booking, staff invitations, form notifications) INSERTS a row into `app_private.email_outbox`; the `email-worker` edge function (pg_cron every minute + a "Send now" kick) delivers it through the Gmail API as the acting PM's Google account (fallback: startups@), one message per recipient. The UI only shows the real delivery state and offers the few actions a person may take. Never a token, a secret or a body of somebody else's project reaches the browser.
- **Where it shows**: the project header link **Outbox** (badge = e-mails that failed, need review or wait for a sender) -> `/projects/:id/outbox?node=<id>&state=<state | attention>` (`OutboxPanel`: chips with counts for needs review / failed / waiting / queued / sending / sent, search by recipient or subject, node filter, per-row details drawer (`OutboxDetail`: what happened in plain words, the Message-ID and the exact Gmail search for an unknown outcome, the sanitised message, the history with the person behind a manual step), bulk and per-row retry, cancel, mark as sent and send again with confirmations that spell out what cannot be undone, "Send now", refreshes on focus and every 10 s while mail is on its way, no socket); the Selection E-mails tab and the Booking Bookings tab show `NodeOutboxSummary` ("12 sent, 2 on the way, 1 need attention" + a link into the Outbox + "Send waiting e-mails now") and the real state of each recipient's e-mail (`OutboxStateBadge`: queued / waiting / sending / sent / failed / needs review / cancelled, every state with its own icon AND word); `/admin/staff` shows each invitation e-mail's delivery state with "send again"; a super_admin gets **E-mail** in the navigation = `/admin/email` (`EmailHealthPanel`: is the worker running (a stalled worker with mail waiting is shown), scheduler on / off, queue depth / due / waiting / held / sending / needs review / oldest, last 24 h, why mail is held back, every sender against 30 a minute and 1,500 a day).
- **Rules for any new screen**: take the STATE from the server (`row.state`), never derive a new one; which actions are allowed per state is `rowActions` in `lib/outbox.js` (the same rules the SQL enforces; rows that do not qualify are skipped and counted); an **unknown outcome (`needs_review`) is never sent again by the platform**: only a person marks it sent, sends it again on purpose (a confirmation) or cancels it; a human sentence for every blocked reason / error code lives in `shared/outbox/i18n.js` (ar + en, tested for parity and for coverage of every code `lib/outbox.js` knows); a NEW `email_key` needs `emailKeyLabel` + `outbox.key.*` there and a branch in the `email_outbox_scope_chk` CHECK.
- **Running it locally (fake Google only)**: `bash db/scripts/dev-functions.sh up` (adds `EMAIL_WORKER_SECRET`, serves the function), then either `bash db/scripts/trigger-email-worker.sh` (one run now) or `bash db/scripts/email-worker-schedule.sh enable` (pg_cron every minute; `disable` / `status`; NOTHING is scheduled by default). `node db/scripts/verify-email-worker.mjs` is the end-to-end proof (103 checks); `db/verify/v62_email_worker.sql` the SQL one (167); `npm run test:edge` runs the function's tests. Commands and env names: `db/README.md`.
- **Tests**: `lib/outbox.test.js`, `data/outbox.test.js` (RPC names / arguments pinned to m62), `shared/outbox/outbox.test.jsx` (panel, bulk actions, confirmations, details, node summary, health panel, invitation delivery, translation parity).
