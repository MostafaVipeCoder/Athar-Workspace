# Athar web (new frontend skeleton)

The new Athar frontend (design `docs/design/06-frontend-architecture.md`). Lives beside the old app (`src/` at the repo root), which stays the deployed one until cutover. Stack: React 19 + JavaScript + Vite 7 + Tailwind 3 + react-router-dom 7 + TanStack Query 5 + supabase-js. The project canvas (`@xyflow/react`, React Flow 12) is lazy-loaded only on `/projects/:id` (one chunk, see "Canvas"). SheetJS (`xlsx`) is loaded only through `lib/export/xlsx.js` (dynamic import).

## Run

Prerequisite: the local Supabase stack is running (`cd local-db/stack && npx supabase status`).

```
cd web
npm install
cp .env.example .env.local     # then fill the two VITE_SUPABASE_* values (see below)
npm run dev:local              # http://127.0.0.1:5174  (mode "development", reads .env.local)
#   (from the repo root: npm run dev:local --prefix web; .claude/launch.json has a "web-local" entry)
npm run build && npm run preview
npm run lint
npm test                       # Vitest + Testing Library
```

`.env.local` is git-ignored. Local values: `VITE_SUPABASE_URL=http://127.0.0.1:54321` and the local anon key printed by `npx supabase status -o env` (`ANON_KEY`). Never commit keys. If a variable is missing the app shows a bilingual ConfigError screen (no fallback to a live project). `EnvBanner` shows green "LOCAL DB" or red "LIVE DATA" from the URL host.

Variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_APP_ENV` (local|staging|production), `VITE_BASE_PATH` (default `/`; router basename and asset base), `VITE_APP_PUBLIC_URL` (optional).

On some Windows machines port 5174 sits in a reserved (excluded) TCP range and cannot be bound (`netsh interface ipv4 show excludedportrange protocol=tcp`): run `npx vite --mode development --host 127.0.0.1 --port 5400` instead.

## Key behaviours

- Auth: `AuthProvider` is query-based (roles from `user_roles` under RLS; no role cache in storage; the cache is wiped when the identity changes). `RequireAccess` is the only guard (decision table in `lib/access.js`, unit-tested); `/` is `RoleHome`.
- i18n: `useLanguage()` gives `t, tn, pick, formatDate, formatNumber, lang, dir, setLang`. Resolution: `?lang=` then stored `athar.lang` then default per area (staff `en`, rest `ar`). `<html lang dir>` is set once. Western digits in Arabic.
- Legacy URLs: `app/legacy/legacyRedirects.js` (one table + boot shim for `#/...` and `?agenda=`).
- Placeholder routes render `ComingSoon` with the step number from design 06 section 14.
- Time: store UTC, build/display wall-clock values only through `lib/time` with the PROJECT timezone (`projects.timezone`, one IANA zone, default Africa/Cairo). Never `new Date('YYYY-MM-DD')`.
- Images: `data/storage.uploadImage(file, { ownerId, kind })` resizes in the browser and stores `<owner>/<kind>/<uuid>.webp` + `<uuid>_t.webp` in `public-assets`; the DB keeps only the full path (`publicThumbUrl` derives the thumbnail).
- Staff management (super_admin): `/admin/staff` lists staff, changes roles / program access, removes, invites by e-mail (RPCs of migration m24). The invitation link is shown once (copy button) because e-mail delivery is not wired yet. Invitees register at `/invite/staff/:token` with name + password + colour only; the DB trigger never grants `founder` on that path. `/profile` edits name, colour, language, password.

## Canvas (`src/app/canvas`, design 06 section 3)

- `ProjectPage` renders the header and `lazy(() => import('../canvas/ProjectCanvas.jsx'))`: that file is the only one importing `@xyflow/react` (and its CSS), so the canvas chunk (about 200 kB / 66 kB gzip) is paid only by PMs on the canvas route. Attribution stays on (owner, 08 section 14).
- Data: one query `get_project_graph` (`useProjectGraph`, nodes without config + edges + revisions) and the mutations of `data/canvas.js` (`useCanvasMutations`): `add_node`, `move_nodes` (optimistic, debounced 800 ms after a drag, never bumps a revision), `delete_node` (soft delete) / `restore_node` (the Undo in the toast), `connect` / `update_edge` / `disconnect`, rename through `save_node` (optimistic-concurrency token = the node's rev), duplicate (= `add_node` of the same type + extension options + `save_node` of the config). Every success refetches the graph; errors are shown by the canvas (toast + inspector status), not by the global reporter.
- Pure logic in `canvasModel.js` (unit-tested): `validateCanvasConnection` mirrors design 02 section 2.5 and the DB trigger `validate_edge` (families, kind, duplicate, cardinality, then `wouldCycle` = DAG **per port family**, decision 02-13). The DB is the authority: when it rejects a connection the server message is shown. Also graph -> React Flow mapping (`toFlowNodes`/`toFlowEdges`, colour per family), default names (`"<Type> N"`), overlap-free placement, sidebar items (booking presets expanded).
- UI: `ToolSidebar` (registry groups, search, drag source + tap "+" which adds at the viewport centre; collapsible on phones), `NodeCard` (memoised; one `<Handle>` per port: inputs LEFT, outputs RIGHT in both languages because the canvas world is `dir="ltr"`; the card text follows the UI direction), `NodeInspector` (summary, status saved/saving/error + "updated just now" flash from the revision poll, ports with counterparts, View/Edit/Settings links, rename/duplicate/delete; edge: audience + enabled + remove; right column on desktop, bottom sheet on phones). The implicit `view_host` system node is shown locked (not deletable) with a link to the public project page.
- Keyboard: Delete/Backspace removes the selection (ConfirmDialog first), Esc deselects. Multi-user: `useSavedStateRefresh` polls `get_graph_revisions` (focus + 30 s); a changed or new/removed node refetches the graph and flashes the changed cards.

## Mentoring Distribution node (`src/nodes/distribution`, design 01 section 3.7, 02 section 4/12, 03 section 9.4, decision 01-7)

- The fixed timetable of the offline 1-1 sessions in the hall: mentor x round x day -> company. Ports mirror the DB row: in `mentors` + `companies` (Lists' `items`, BY REFERENCE: sessions point at `list_items` ids, names/photos are resolved by the DB, never stored on a session), optional `schedule` (an Agenda's days: `distribution_days.agenda_day_id` supplies the date; without it the node keeps its own date, 02-12); out `sessions-tab` (the matrix) and `my-meetings-tab` ("My schedule / Who do I meet next") = Agenda tabs through the tab contract. The Live board is a standalone page.
- Rules (01-7): ONE break model = the per-day gap; total round = slots + gaps (`lib/time/slots`); a locked day is never overwritten (Generate, Regenerate, config saves, removal all refuse it); unique pairing is per node; the project timezone is used everywhere (`lib/time`), "today" included.
- **The algorithm** (`matching.js`, pure + seeded + unit-tested): per round ONE optimal assignment (Hungarian) maximising filled cells, then fairness, then a seeded jitter; 8 attempts, best kept; windows / allowed days / max per day honoured by every path; every empty cell explained. The server never trusts it: `replace_distribution_sessions` re-validates every row and swaps the sessions atomically. Manual edits (drag/swap/move, click dialog, clear) are ONE `set_distribution_session_companies` call each (hard conflicts raise, repeated pairs warn) with an Undo toast = the inverse call; sessions have DB ids from creation.
- Edit = Setup (round, days, mentors x days, availability: window / max per day / room; draft + ONE `save_node` with children) / Timetable (Generate, Regenerate unlocked, per-day lock and regenerate, seed, matrix editing, issues, publish, Excel, print) / Live (PM remote + board). Settings = name, visibility, show-to-participants, publish, timer alert + sounds, the Matrix and Live links. View = the PM preview of the three surfaces.
- **Surfaces**: `MatrixTab` (Agenda tab `sessions-tab` + `/view/:ref/matrix`, wide shell, print landscape), `MyScheduleTab` (Agenda tab `my-meetings-tab`, mobile-first: company picker or the signed-in founder's own company, now/next with room and time, mentor mode), `LiveBoard` (`/view/:ref/live`: big countdown, who meets whom now/next, tick/alarm sounds the viewer enables, full screen). The DB enforces the publish flag and the audience (`get_distribution_view`, `get_public_tab`); legacy `/view/<event id>/mentoring/matrix|live` links keep working.
- **Timer (03 section 9.4, as-is SEC-5 closed)**: the state is one row of SERVER TIMESTAMPS (`distribution_timers`: status, `ends_at` / `remaining_s`, the round pointer, a version); the ONLY writer is `distribution_timer_control` (PM only; set round, start/pause, adjust, reset, next/previous, clear); visitors read a tiny RPC every 5 s while the page is visible and every screen computes the remaining time locally (`timerRemaining`). No public control channel, no Realtime, nothing written per second. Without a timer round the board follows the project-zone clock.
- DB: `db/migrations/m35_distribution.sql` + `db/verify/v35_distribution.sql` (see `db/MIGRATION-LOG.md`).

## Resource Library node (`src/nodes/library`, design 01 section 3.8, 03 sections 6.2 + 11, 04 section 3.11)

- Rows: `resources` (title/description ar+en, type readable|audible|visual|link, `url` OR `file_path`, mime, bytes, `cover_path`, **`visibility` public | participants | hidden**, `category_id`, `sort_order`, soft delete) + `library_categories` (the sections, ar/en, ordered). ## Add a node type

1. Create `src/nodes/<folder>/manifest.js` with `defineNode({ key, version, name:{en,ar}, icon, category, ports:{in,out}, ... })`. Ports use families from `manifest.contract.js`; `key` must match a row in `public.node_types`.
   A port is `inPort(key, families[], label{en,ar}, { kind?, cardinality: 'one'|'many', required? })` / `outPort(...)` (helpers in `_kit/defineNode.js`). The canvas draws one handle per port; an edge is allowed when the output's FIRST family is accepted by the input, kinds match (list `items` is `kind: 'subkind'`, decided server-side from `lists.subkind`), the pair is not connected yet, the input's cardinality is not exceeded and no cycle appears within that family. Keep the manifest in sync with the `node_types.ports` row (m02) — the DB validates the same rules.
2. Components default to the shared placeholder. For real screens create `Edit.jsx`, `View.jsx`, `Settings.jsx` in the folder and set `components: { Edit: () => import('./Edit.jsx'), ... }` (lazy thunks, default exports).
3. Use the kit only: `useNodeConfig()` (draft + explicit Save + refresh; `save(extraPatch)` may add `name_en/ar`, `visibility`, `show_to_participants`), `useInputPort(key)` (reads upstream data through the SOURCE node's `ports.out[].resolve` thunk), `NodeFrame` (`showSave={false}` for row-level editors, `actions`, `subtitle`), `useNodeContext()`. Never import Supabase or another node; data goes through `data/` modules.
4. For an output port other nodes can read, give it `resolve: () => import('./data.js').then(m => m.resolveX)`; the resolver gets `{ node, port, adapter, graph }` and returns `{ items }`.
5. Register it in `src/nodes/registry.js`. `registry.test.jsx` validates the contract for every manifest.

The dev-only `note` node (`src/nodes/note`, playground at `/dev/nodes`) is the worked example. It is excluded from production builds (`devManifests.prod.js` alias in `vite.config.js`).
