# Shared brief for node builders (web/)

You are building ONE node type (or one feature) of the NEW Athar frontend in `web/`, against the LOCAL migrated Supabase stack. Several builders run one after another; each must leave the app green (lint, tests, build) and the local DB at baseline.

## Read first
- `web/README.md`, `web/PROGRESS.md` (status, deviations, conventions), the existing `web/src` code: registry/manifests (`src/nodes/`), `NodeHost`, `useNodeConfig`, `useInputPort`, `useSavedStateRefresh`, `data/` modules, `ui/` kit, `lib/` (time/tz/slots, links, contact, export/xlsx, image), canvas (`src/app/canvas/`), Programs/Project pages, StaffPage patterns.
- Design: `docs/design/01-node-catalog.md` (YOUR node's section: purpose, config schema, ports, views, multiplicity, visibility, emails, founder exposure, must-not-carry bug list), `02-data-flow-and-connections.md` (reference + overlay list items, ensure_item, resolve_list, revisions, participants, agenda tabs), `04-database-design.md` (tables/RPCs for your node — VERIFY what exists in the DB: `docker exec -i supabase_db_stack psql -U postgres -d postgres` and `db/migrations/m0*.sql`, `m2*.sql`), `03-roles-permissions-and-rls.md`, `06-frontend-architecture.md`, `07-emails-integrations-and-certificates.md` (emails/calendar/certificates/share), `08-decisions-log.md` (OWNER DECISIONS OVERRIDE EVERYTHING; read all sections), `docs/13-refactor-vision-and-decisions.md` (owner's product description), and for the Landing node `landing-page.html` at the repo root.
- As-is behaviour to preserve (features, not bugs): `docs/03`, `04`, `05`, `06` as-is documents for your area, and the migrated data in the local DB (real projects exist: use them READ-ONLY for visual checks; create throwaway projects/nodes/rows for write tests and delete them).

## Rules
- Stack: React 19 + JavaScript (no TypeScript) + Vite + Tailwind + react-router 7 + TanStack Query. Light: each node's Edit/View/Settings components are lazy chunks; no persistent sockets for visitors; images via `ui/Img` with thumbnails; queries select needed columns; no N+1.
- Data flow: connected data is read by reference through input ports/resolvers (never copy rows); list items = reference + overlay; explicit Save bumps the node revision (use the save RPCs with expected_rev); drafts are client-side.
- UX (owner goal: best possible UX, fast and light): mobile-first for founder/public views, desktop-first for PM editors; Arabic RTL + English; empty/loading/error states on every list; confirmations only for irreversible actions (ConfirmDialog, never native alert/confirm/prompt); undo where feasible; accessible (labels, focus, keyboard, contrast, tap targets ≥ 44px); consistent with the existing ui kit — extend it rather than fork it.
- DB: NEVER use Supabase MCP tools or the live project. If your node needs SQL that does not exist (table/column/RPC/policy), add a NEW re-runnable migration `db/migrations/m3N_<node>.sql` (+ `db/verify/v3N_*.sql` role-switch checks) following 03/04 conventions (RLS enabled+forced, policies per family, helpers in app_private with search_path='', explicit grants, SECURITY DEFINER only where 03 allows), run it on the local DB, log it in `db/MIGRATION-LOG.md` and `db/README.md`. Never alter migrated business data; never print secrets/PII.
- Do not touch the old app (`src/`, root configs, `supabase/`), `.gitignore`, or `docs/` (append to `web/PROGRESS.md`, `web/README.md`, `db/MIGRATION-LOG.md`, `db/README.md` only). No git commit/push.
- Verification before you finish: `npm run lint`, `npm test` (add tests for your node's logic and components), `npm run build` (report your chunks' sizes), browser check on the local stack (`npm run dev:local`; use the mcp__Claude_Browser__* tools) in Arabic and English, desktop and 375 px phone, covering Edit, View (public and platform audiences), Settings, connection to the nodes it depends on (use the canvas), and the founder-facing exposure if any. Clean up all throwaway data; verify baseline counts: 12 users/profiles/roles, 4 programs, 16 projects, 82 nodes, 53 edges, 141 companies, 44 program_members, 0 staff_invitations, 82 node_revisions (or document the exact delta you intentionally left, which should be none). Stop the dev server.
- Append to `web/PROGRESS.md`: what is done, deviations from 01/02/04/06 with reasons, open questions for the owner, what the next builder must know (hooks/components you added that others should reuse).

## Final report (short, no secrets/PII)
What was built; DB changes; verification results (tests/lint/build sizes/browser); deviations; open questions; handover notes.
